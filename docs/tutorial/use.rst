=================
Use the dashboard
=================

The dashboard is public: you do not need to sign in to use it. It shows the
public repositories of PyCalendar where its GitHub App is installed.

Find something to work on
=========================

1. Open `dashboard.pycal.org <https://dashboard.pycal.org>`_. The start page
   shows the numbers of the community and four lists: *Start here*, *Waiting
   for a review*, *Issues without an answer* and *Welcome, first
   contributors*.
2. Choose **Contribute** in the menu. *Issues for newcomers* are open issues
   labeled ``good first issue``, ``help wanted`` or ``easy``.
3. Open an issue on GitHub, say in a comment that you work on it, and open a
   pull request when you are ready. It appears on the dashboard, and reviewers
   find it on the page *Reviews*.

An issue without an answer is a good start, too: a question, a test or a
confirmation of the bug helps the maintainers.

Review pull requests
====================

Everybody can review. Choose **Reviews** in the menu: the pull requests that
wait for a review come first, the longest waiting at the top. Read the change,
try it and say what you found. *Without activity* lists pull requests that may
need a reminder, help or a decision.

Look at a repository
====================

Choose **Repositories** and a repository. Its page shows its numbers and its
issues and pull requests. Filter them by state (open, closed) and kind (pull
requests, issues).

The period
==========

Some numbers count a period, such as the merged pull requests and the
contributors. Choose 30 days, 90 days or a year with *Period*; the address keeps
it, such as ``?days=30``.

Contributors
============

**Contributors** lists the people who opened issues or pull requests in the
period, without bots. Each person has a public page with their open pull
requests and the reviews asked of them. It shows only what is public on GitHub.

When something goes wrong
=========================

An error page says what happened, gives details to copy and links to the
description of the error in :doc:`/reference/errors`, which says why it
appears and how to resolve it.
